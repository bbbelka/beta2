## 1. Executive Summary

MAISON D'ANTIQUE — это статический сайт-витрина антикварных товаров с корзиной, избранным, личным кабинетом, чатом и админ-панелю. Основная часть каталога (~75 товаров) жёстко закодирована в `js/catalog.js` и импортируется из Avito. Серверная часть — Supabase (Auth, Realtime, Storage, Edge Functions).

**Общая оценка:** сайт функционален, но имеет несколько критических и высоких проблем в безопасности, производительности и отсутствии автоматизированного тестирования.

**Ключевые выводы:**
- Jeton anon ключа Supabase открыт в клиентском коде (`js/config.js`) — приемлемо для Supabase, но требует строгих RLS-политик.
- RLS настроен корректно для продуктов, профилей, заказов и хранилища фото.
- Отсутствует `send-inquiry` Edge Function (директория пустая) — потенциальная точка отказа при оформлении заявок.
- Нет системы автоматического тестирования (только 4 изолированных тестовых файла в `/tests`).
- Каталог жёстко задан в JS-файле; синхронизация с Supabase не реализована для уже существующих товаров.
- Нет Service Worker кэширования strategій кроме базового `sw.js` (требуется проверка).
- Отсутствуют микроразметка Schema.org и ограниченный набор meta-тегов для SEO.

## 4. Supabase & Backend Analysis

### 4.1 Проект Supabase
- URL: `qxaokgxjahojcqevlwhb.supabase.co`
- Anon ключ: открыт в `js/config.js` (стандартная практика для Supabase)

### 4.2 База данных (`supabase-schema.sql`)

**Таблицы:**
- `profiles` — профили пользователей (id, email, role: user|admin, created_at)
- `products` — каталог товаров (id, avito_id, name, price, seller, category, year, image, photos, link, description, available, sold_at, created_at, updated_at)
- `orders` — заказы (id, user_id, items, customer, address, delivery, total, status, tracking_number, status_note, created_at, updated_at)

**RLS-политики:**
- `profiles`: читать свой профиль или любой (для админов), вставка/обновление только своего id
- `products`: публичное чтение (anon + authenticated), запись только для админов через `is_admin()`
- `orders`: чтение своих заказов или всех (для админов), вставка только своих

**Функции:**
- `handle_new_user()` — триггер на создание профиля при регистрации
- `is_admin()` — проверка роли администратора (security definer)
- `create_shop_order()` — УСТАРЕВШАЯ, вызывает исключение (требует `inventory-migration.sql`)

**Storage:**
- Корзина `product-photos` (публичное чтение, запись только для админов, лимит 8 МБ, допустимые MIME: jpeg, png, webp, gif, avif)

### 4.3 Миграции
- `inventory-migration.sql` — добавляет колонки `available`, `sold_at` к продуктам
- `messages-migration.sql` — таблица сообщений/диалогов
- `profile-migration.sql` — расширение профилей
- `purchase-request-migration.sql` — заявки на покупку
- `chat-archive-migration.sql` — архив чатов
- `availability-only-order-migration.sql` — заказ только по наличию

### 4.4 Edge Functions

**`supabase/functions/send-push/index.ts`** (64 строк):
- Отправляет веб-уведомления через VAPID при новом сообщении
- Требует авторизации (Bearer токен)
- Проверяет права отправителя на сообщение
- Использует `SUPABASE_SERVICE_ROLE_KEY` (серверный ключ, не клиентский)
- Удаляет неактивные подписки push при ошибках 404/410

**`supabase/functions/send-inquiry/`** — **пустая директория**, нет `index.ts` или другого файла. Это потенциальная точка отказа, если клиентский код пытается вызвать эту функцию.

### 4.5 Проблемы бэкенда
- `create_shop_order()` выбрасывает исключение — устаревший контракт, требует применения `inventory-migration.sql`
- `send-inquiry` Edge Function отсутствует (пустая директория)
- Нет очереди задач для обработки заказов вне Edge Function
- Нет webhook-обработчиков для платежных систем

1. **Реализовать `send-inquiry` Edge Function** — заполнить пустую директорию `supabase/functions/send-inquiry/`, иначе обработка заявок на покупку может не работать.
2. **Применить `inventory-migration.sql`** — устаревшая функция `create_shop_order()` выбрасывает исключение, оформление заказов неработо без миграции.
3. **Защитить anon ключ Supabase** — хотя открытыйanon ключ является стандартом для Supabase, рекомендуется добавить ограничение по доменам в настройках Supabase Dashboard.

### High

4. **Добавить `sitemap.xml` и `robots.txt`** — базовая SEO-оптимизация.
5. **Добавить микроразметку Schema.org** — Product, Organization для улучшения видимости в поиске.
6. **Реализовать пагинацию или бесконечный скролл каталога** — производительность при росте числа товаров.
7. **Добавить обработку 404 страницы** — улучшение UX при несуществующих маршрутах.
8. **Добавить rate limiting на вход и регистрацию** — защита от брутфорса.

### Medium

9. **Минифицировать CSS и JS** — уменьшение размера трафика.
10. **Добавить lazy loading для изображений каталога** — ускорение initial load.
11. **Оптимизировать изображения** — конвертация в WebP, сжатие.
12. **Расширить Service Worker strategиями кэширования** — офлайн-работа, повторные визиты.
13. **Добавить валидацию форм в реальном времени** — улучшение UX.
14. **Добавить skip-to-content ссылку** — доступность.

### Low

15. **Добавить Open Graph / Twitter Card мета-теги** — лучшее представление в соцсетях.
16. **Добавить canonical ссылки** — предотвращение дублирования контента.
17. **Вынести конфигурацию из исходного кода в переменные окружения** — лучшая практика.

### Testing

18. **Внедрить систему автоматического тестирования** (Vitest/Jest + Playwright).
19. **Настроить CI/CD** для запуска тестов при пушах.
20. **Покрыть критические сценарии e2e тестами**: вход, просмотр товара, корзина, оформление заявки, чат.

## 14. Conclusion

MAISON D'ANTIQUE — функциональный статический интернет-магазин с хорошей базовой архитектурой на Supabase. Основные сильные стороны: корректная настройка RLS, админ-панель с управлением товарами и заказами, встроенный чат, дизайн-система, поддержка тем.

Критические проблемыrequiring immediate attention:

2. Устаревшая `create_shop_order()` — оформление заказов неработо без миграции.
3. Отсутствие автоматического тестирования — риск регрессий при изменениях.

После устранения критических проблем сайт будет готов к продакшен-эксплуатации с регулярным мониторингом и постепенным улучшением производительности и SEO.
